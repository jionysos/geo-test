# 최종 리포트 구조

제목은 실행한 모델 수에 따라 "ChatGPT GEO 스냅샷" (1개 모델) 또는
"멀티모델 GEO 스냅샷" (2개 이상)으로 한다. "AI 가시성 점수"처럼 확정적인 단일
점수 표현은 쓰지 않는다.

```markdown
# {브랜드명} ChatGPT GEO 스냅샷 — {측정일자}

## 한계 (맨 위에 명시)
질문 10개, 단일 시점, 반복 측정 없음의 스냅샷입니다. 추세가 아니라 현재 한 장의
사진으로 읽어주세요.

## 핵심 지표

경쟁사를 지정한 경우:
| 브랜드 | 언급률 | 추천률 | 인용률 | Mention SoV | Recommendation SoV |
|---|---|---|---|---|---|
| 자사 | | | | | |
| 경쟁사A | | | | | |
| ... | | | | | |

경쟁사를 지정하지 않은 경우 (SoV 두 열은 표에서 뺀다 — N/A를 나열해봐야 정보가
아니다):
| 브랜드 | 언급률 | 추천률 | 인용률 |
|---|---|---|---|
| 자사 | | | |

## 자사·경쟁사 비교 (질문별)

경쟁사를 지정한 경우:
| ID | 여정단계 | 질문 | 자사 | 경쟁사A | 경쟁사B | 비고 |
|---|---|---|---|---|---|---|

경쟁사를 지정하지 않은 경우, 이 표 대신 아래를 넣는다:

### 답변에 등장한 브랜드 (자동 발견)
| 브랜드 | 등장 질문 ID | 등장 횟수 |
|---|---|---|

반복적으로 등장하는 브랜드가 있으면 "다음 측정 때는 이 브랜드들을 경쟁사로
지정해서 다시 돌려보시면 SoV까지 비교할 수 있습니다"라고 안내한다.

## 자사가 빠진 질문
- Qn: (질문) — 대신 등장한 브랜드: ...

## 경쟁사가 강한 질문

경쟁사를 지정하지 않은 경우 이 섹션은 생략하거나 "발견된 브랜드 중 자사보다
자주 등장한 브랜드"로 대체한다.
- Qn: (질문) — 경쟁사X가 상위 추천, 근거 문장: "..."

## 자주 인용된 도메인
| 도메인 | 등장 횟수 | 연결된 브랜드 |
|---|---|---|

## 테크니컬 문제 ↔ 실제 AI 답변 연결
2단계 진단에서 나온 문제가 6~7단계 결과와 실제로 연결되는지 짚는다.
(예: noindex는 없었지만 구조화 데이터 Product 누락 → 비교 질문에서 자사만
가격·스펙 언급 없이 이름만 나옴 — 데이터 부재가 추천률을 갉아먹는 패턴)
근거 없는 추측이면 "확인 필요"라고 명시하고 단정하지 않는다.

## 검색모드 vs 일반모드 (답변에 출처 URL 유무가 섞여 나온 경우만)
사용자가 모드를 미리 고른 게 아니라, 10개 답변 중 일부는 출처 URL이 붙고 일부는
안 붙는 식으로 자연히 섞여 나올 수 있다. 섞여 있으면 그 차이로 원인을 구분해 짚는다:
- 출처 없는(일반모드) 답변에서도 언급 안 됨 → 브랜드 자체가 모델에 안 알려짐
  (LLMO 부재). 콘텐츠·언급 노출을 넓히는 게 우선
- 출처 없는 답변에선 언급되는데 출처 있는(검색모드) 답변에서만 안 뜸 → 브랜드는
  알려져 있지만 지금 웹 콘텐츠가 검색에 안 걸림(GEO 갭). 위 "테크니컬 문제 ↔
  실제 AI 답변 연결"과 묶어서 원인을 좁힌다
- 전부 한 종류로만 나왔으면(예: 10개 다 출처 있음) 이 섹션은 생략한다

## 우선 개선 과제 (최대 3개)

## 재측정 방법
- 언제: 개선 반영 후 최소 2주 뒤
- 어떻게: `templates/questions.md`의 동일 질문을 새 대화에서 그대로 재실행
- 무엇을 비교: 이번 스냅샷의 지표표와 나란히 놓고 변화량만 본다

## 한계 (다시 한번)
질문 10개·단일 시점 결과입니다. 반복 실행 시 답변이 달라질 수 있어(모델의 응답
변동성), 이 리포트는 트렌드가 아니라 "이 순간의 스냅샷"으로 해석해야 합니다.
```
