# 최종 리포트 구조

제목은 실행한 모델 수에 따라 "ChatGPT GEO 스냅샷" (1개 모델) 또는
"멀티모델 GEO 스냅샷" (2개 이상)으로 한다. "AI 가시성 점수"처럼 확정적인 단일
점수 표현은 쓰지 않는다 — **이건 GEO 쪽(질문 5개·단일 시점이라 노이즈가 큰
실측) 얘기다.** 아래 기술 점수는 다르다 — curl로 확인한 사실(HTTP 상태·메타
태그 존재 등)에서 나온 결정론적 점수라 재실행하면 같은 결과가 나오고, 그래서
숫자로 단정해도 된다. 이 둘을 report.md 안에서 섞어 읽지 않게 구분해서 보여준다.

```markdown
# {브랜드명} ChatGPT GEO 스냅샷 — {측정일자}

## 한계 (맨 위에 명시)
질문 5개, 단일 시점, 반복 측정 없음의 스냅샷입니다. 추세가 아니라 현재 한 장의
사진으로 읽어주세요. (아래 기술 점수는 예외 — curl 사실 기반이라 단정적 숫자임.)

## 사이트 기술 진단
**{점수}/100 ({등급})** — {필수 중 실패 항목 요약, 없으면 "필수 항목 전부 통과"}
| 구분 | 항목 | 상태 | 근거 |
|---|---|---|---|
(tech-audit.md 필수/권장/참고 표 그대로)

## 핵심 지표

**인용률은 계산·표시하지 않는다** — 출처 표시가 브랜드 칩(URL 아님)이라 "+N"
묶음 안의 브랜드를 못 읽는 경우가 있고, 이걸 퍼센트로 내면 검증 불가능한
숫자가 된다(`references/scoring.md` 참고). 대신 SoV를 메인 비교 지표로 쓴다.

경쟁사를 지정한 경우:
| 브랜드 | 언급률 | 추천률 | Mention SoV | Recommendation SoV |
|---|---|---|---|---|
| 자사 | | | | |
| 경쟁사A | | | | |
| ... | | | | |

경쟁사를 지정하지 않은 경우 (SoV 두 열은 표에서 뺀다 — N/A를 나열해봐야 정보가
아니다):
| 브랜드 | 언급률 | 추천률 |
|---|---|---|
| 자사 | | |

표 바로 아래에 **산식을 한 줄로 밝힌다** — 숫자만 던지면 "왜 이 값이지" 검증이
안 된다:
> 언급률 = 언급된 답변 수 / 전체 질문 수 · 추천률 = 추천된 답변 수 / 추천이
> 성립할 수 있는 질문 수 (`references/scoring.md` 참고)

## 질문별 결과

여정단계·"자사 빠짐" 여부를 따로 안 적는다 — 아래 O/X 표 자체가 그 정보다.
경쟁사를 지정했든 자동 발견했든 같은 표 형식을 쓴다. **인용 컬럼은 넣지
않는다** — 위와 같은 이유(출처 칩의 "+N" 묶음 맹점)로, 개별 질문 단위 O/X로
표시해도 똑같이 신뢰할 수 없다:

| ID | 질문 | 언급 | 추천 | 등장 브랜드 |
|---|---|---|---|---|
| Q1 | (질문 요약) | O/X | O/X | 경쟁사X, 경쟁사Y |

"등장 브랜드"엔 그 답변에 나온 자사 외 브랜드를 전부 배지처럼 나열한다(지정
경쟁사든 자동 발견 브랜드든 구분 없이). 아무도 안 나왔으면 "—".

**표 아래에 질문별로 AI 응답 원문(또는 충분히 긴 발췌)을 접어서 붙인다** —
한 줄 요약("경쟁사 추천됨")만으로는 판정 근거를 검증할 수 없다. 마크다운에서도
`<details>` 태그를 그대로 쓴다(GFM 렌더러에서 접기/펼치기로 보이고, 일반
텍스트로 열어도 그냥 읽힌다):

```markdown
<details><summary>Q1 응답 보기</summary>

(사용자가 채팅에 붙여넣은 원문 그대로 — 요약하지 말고 판정에 쓴 만큼은 남긴다)

</details>
```

## 답변에서 발견된 경쟁사
| 브랜드 | 등장 질문 ID | 등장 횟수 |
|---|---|---|

경쟁사를 지정하지 않았고 반복적으로 등장하는 브랜드가 있으면 "다음 측정 때는
이 브랜드들을 경쟁사로 지정해서 다시 돌려보시면 SoV까지 비교할 수 있습니다"라고
안내한다. (HTML 리포트에서는 이 표를 막대그래프로도 보여준다 — `html-report.md`
참고. 마크다운은 표만 유지한다, 이미지 렌더링을 보장할 수 없어서.)

## 경쟁사가 강한 질문

경쟁사를 지정하지 않은 경우 이 섹션은 생략하거나 "발견된 경쟁사 중 자사보다
자주 등장한 브랜드"로 대체한다.
- Qn: (질문) — 경쟁사X가 상위 추천, 근거 문장: "..."

## 자주 인용된 도메인
| 도메인 | 등장 횟수 | 연결된 브랜드 |
|---|---|---|

**완전한 집계라고 주장하지 않는다** — 눈에 보이는 출처 표시를 그대로 옮겨
적은 관찰 목록이다("+N" 묶음 안에 더 있을 수 있음). 비율·순위로 해석하지
말고 "이런 곳들이 보였다" 정도로만 읽는다.

## 테크니컬 문제 ↔ 실제 AI 답변 연결
2단계 진단에서 나온 문제가 6~7단계 결과와 실제로 연결되는지 짚는다.
(예: noindex는 없었지만 구조화 데이터 Product 누락 → 비교 질문에서 자사만
가격·스펙 언급 없이 이름만 나옴 — 데이터 부재가 추천률을 갉아먹는 패턴)
근거 없는 추측이면 "확인 필요"라고 명시하고 단정하지 않는다.

## 재측정 방법
- 언제: 개선 반영 후 최소 2주 뒤
- 어떻게: 아래 부록의 동일 질문을 새 대화에서 그대로 재실행
- 무엇을 비교: 이번 스냅샷의 지표표와 나란히 놓고 변화량만 본다

## 한계 (다시 한번)

변동성), 이 리포트는 트렌드가 아니라 "이 순간의 스냅샷"으로 해석해야 합니다.
