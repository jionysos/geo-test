# 질문 10개 생성 규칙

목적은 "브랜드를 몰라도 이 니즈로 검색하면 AI가 뭐라고 답하는지"를 보는 것이다.
그래서 **질문에 자사·경쟁사 브랜드명을 절대 넣지 않는다** — 브랜드명이 들어가면
AI가 그 브랜드를 중심으로 답해서 자연 노출을 측정할 수 없다.

## 고정 구조 (총 10개)

추천 비교가 이 스킬의 핵심 산출물이라 그 비중을 가장 크게 잡는다. 나머지 단계는
"AI가 이 니즈 자체를 인지하는가 / 어떤 후보군을 떠올리는가"를 최소 개수로만
확인하는 용도다.

| 여정 단계 | 개수 | 이 단계가 보는 것 |
|---|---|---|
| 1. 문제 인지 | 1 | 증상·불편·니즈를 어떻게 표현하고, AI가 어떤 해결 방향을 먼저 제시하는가 |
| 2. 해결책 탐색 | 2 | 어떤 종류의 제품·서비스·방법을 후보로 올리는가 |
| 3. 브랜드·제품 추천 | 6 | 실제로 이름을 몇 개나, 어떤 순서로 추천하는가 — 언급률·추천률·SoV의 핵심 표본 |
| 4. 비교·선택 | 1 | 후보 간 비교 기준을 뭘로 잡고 누구를 우위에 두는가 |

## 작성 기준

- `templates/brand_profile.md`의 "주요 제품·서비스와 타깃 고객" 문구를 그대로
  가져다 쓰지 말고, **그 타깃 고객이 실제로 검색창에 칠 법한 말투**로 바꾼다.
  (예: 브랜드 설명이 "반려동물 영양제"여도 질문은 "강아지가 자꾸 눈물 흘리는데
  뭘 먹여야 하나요" 처럼 증상·상황형으로.)
- 목표 국가·시장·언어에 맞춘다 — 해외 타깃이면 해당 언어로 질문을 만들고, 그 시장의
  검색 습관(예: 미국은 브랜드 비교형이 흔함)을 반영한다.
- 질문 하나당 하나의 니즈만 담는다. 복합 질문은 어느 지점에서 브랜드가 빠졌는지
  판정하기 어렵다.
- 브랜드/제품 카테고리명은 써도 되지만(예: "강아지 유산균") 구체 브랜드명은 금지.

## 저장 형식 (`templates/questions.md`)

```
| ID | 여정단계 | 질문 | 비고 |
|---|---|---|---|
| Q1 | 문제인지 | ... | |
| Q2 | 해결책탐색 | ... | |
| Q3 | 해결책탐색 | ... | |
| Q4 | 브랜드제품추천 | ... | |
| Q5 | 브랜드제품추천 | ... | |
| Q6 | 브랜드제품추천 | ... | |
| Q7 | 브랜드제품추천 | ... | |
| Q8 | 브랜드제품추천 | ... | |
| Q9 | 브랜드제품추천 | ... | |
| Q10 | 비교선택 | ... | |
```

ID와 여정단계는 이후 5~8단계 전부에서 이 표를 기준으로 참조한다 — 생성 후에는
바꾸지 않는다(바꾸면 재측정 시 동일 질문 비교가 깨진다).
