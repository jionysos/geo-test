# 수동 측정 안내

이 스킬은 외부 AI API를 호출하지 않는다. **사람이 직접 각 서비스에 질문을 넣고
답변을 가져오는 것이 유일한 데이터 소스다.** 이 문서는 그 과정을 최대한 짧고
실수 없게 만드는 게 목적이다.

## 모드는 미리 고르지 않는다 — 답변을 보고 사후 판별한다

ChatGPT는 모델·버전에 따라 "검색 켜기/끄기"를 대화마다 명확히 고르는 스위치가
없을 수 있다(자동으로 검색 여부를 판단하는 방식으로 바뀌는 추세). 그러니 사용자한테
"검색모드로 실행해주세요"라고 시키지 않는다 — **그냥 질문을 넣고, 나온 답변에
출처 URL이 붙어 있는지로 사후 판별**한다.

| 답변에 출처 URL이 있으면 | 없으면 |
|---|---|
| 검색이 개입한 답변 — GEO 신호. 인용률 계산 가능 | 순수 기억 기반 답변 — LLMO 신호. 인용률은 N/A |

같은 질문을 두 번 실행했을 때 한 번은 출처가 붙고 한 번은 안 붙는 식으로 결과가
갈리면, 그 둘을 비교해서 **"AI가 아예 모르는 건지 vs 알긴 아는데 검색 결과에서만
안 뜨는 건지"**를 구분할 수 있다 — 출처 없는 답변에서도 언급이 안 되면 브랜드
자체가 안 알려진 것(콘텐츠 노출을 넓혀야 함), 출처 없는 답변에선 언급되는데
출처 있는 답변에서만 안 뜨면 지금 웹 콘텐츠가 검색에 안 걸리는 것(사이트·콘텐츠
문제, 2단계 기술진단과 연결). 이건 강제로 만들어낼 필요 없이, **10개 질문을
돌리다 보면 자연히 두 종류가 섞여 나오니 그걸 그대로 활용**하면 된다. 설정에서
검색을 끌 수 있는 옵션이 있는 모델·플랜이면 그걸 써서 의도적으로 만들어도 되지만
필수는 아니다.

- 질문마다 **새 대화**에서 실행한다. 같은 대화창에서 이어서 물으면 이전 질문의
  맥락이 다음 답변에 영향을 줘서 독립 측정이 안 된다.
- 질문 문구는 `templates/questions.md`에 저장된 그대로, 토씨 하나 안 바꾸고 붙여넣는다.

## 절차 (질문 10개 × 선택한 모델 수 만큼 반복)

1. 새 대화 시작
2. `templates/questions.md`에서 질문 ID 하나를 그대로 복사해 입력
3. 답변이 끝날 때까지 기다린다 (검색 중이면 완료까지)
4. 답변 **전체 텍스트**를 복사 (일부만 복사하면 뒤쪽에 나온 언급을 놓친다)
5. 화면에 표시된 출처/인용 URL이 있으면 전부 복사 (각주 링크, 하단 출처 목록 등)
6. `templates/responses.md`에 아래 형식으로 붙여넣기

```
### Q1 — ChatGPT

**질문:** (그대로)

**답변 전문:**
(붙여넣기)

**표시된 출처 URL:**
- ...(없으면 "없음"이라고 적는다 — 이게 곧 일반모드/LLMO 신호다)
```

헤더에 모드를 미리 적지 않는다 — 6단계에서 답변에 출처 URL이 있었는지를 보고
`(검색모드)`/`(일반모드)`를 스킬이 사후에 붙인다. 사용자는 그냥 물어보고
붙여넣기만 하면 된다.

## 선택: 추가 모델

Gemini·Perplexity·네이버(Cue: 등)도 원하면 같은 형식으로 추가한다. 모델마다
섹션을 나눠서(`### Q1 — Perplexity`) 같은 질문 ID 아래 모아두면 6단계 분석이
쉬워진다. 총 실행 횟수(질문10 × 모델수)가 늘어난다는 것만 미리 안내한다 —
무리해서 다 채우지 않아도 된다, 모델 1개만으로도 스냅샷은 나온다.

## 흔한 실수

- 출처 URL이 안 붙은 답변을 두고 "인용률이 왜 0%냐"고 묻는 경우 → 그 답변은
  애초에 인용률 계산 대상이 아니라 N/A(LLMO 신호일 뿐)
- 질문을 대화 맥락 안에서 이어 물어서 브랜드가 먼저 언급된 경우 → 새 대화로 다시
- 답변 앞부분만 복사해서 뒤에 나온 경쟁사 언급을 놓치는 경우 → 전체 복사 원칙
- 출처 URL이 있는지 없는지 확인 안 하고 붙여넣는 경우 → "없음"이라도 반드시 적는다,
  빈칸으로 두면 6단계에서 모드 판별이 안 됨
- 오늘 측정한 걸 다음 주 결과와 섞어서 비교하는 경우 → 측정 시점(날짜)을 항상
  같이 기록한다
